# QA/Tester Dashboard

## What

A local-only page at `/dev/qa` in the admin app that visualizes E2E test results. Reads from `test-results/logs/test-run-*.json` files generated by the existing Playwright JSON logger.

## Why

Currently, understanding test results requires reading raw JSON or scrolling through terminal output. A visual dashboard lets you:
- See pass/fail at a glance per server
- Drill into which step failed and how long each step took
- Compare runs over time
- Spot slow tests and bottlenecks

## Data Source

Existing: `test-results/logs/test-run-{timestamp}.json` — contains:
```json
{
  "timestamp": "2026-06-17T...",
  "status": "passed|failed",
  "duration": 350000,
  "total": 128, "passed": 128, "failed": 0,
  "tests": [{
    "suite": "Admin Dashboard",
    "test": "create doctor",
    "status": "passed|failed",
    "duration": 4700,
    "steps": [
      { "title": "Fill: doctor-username", "duration": 120, "status": "passed" },
      { "title": "Assert: temp-password visible", "duration": 15000, "status": "failed" }
    ],
    "errors": ["expect(locator).toBeVisible() failed..."],
    "retries": 0
  }]
}
```

## The Problem: Getting Data to the Browser

The JSON files live on disk at `test-results/logs/`. The admin app is a Next.js frontend. We need a way to serve these files to the browser.

### Options

**Option A: Backend API endpoint**
- Add `GET /api/test/reports` and `GET /api/test/reports/:filename` to testRoutes.js
- Reads from `test-results/logs/` directory
- Pros: clean, works with existing backend, can add filtering
- Cons: couples test reporting to the backend server

**Option B: Next.js API route in admin app**
- Add `apps/admin/app/api/test-reports/route.ts`
- Reads from `../../test-results/logs/` 
- Pros: self-contained in admin app, no backend changes
- Cons: Next.js API routes add complexity, path resolution tricky in monorepo

**Option C: Static file serving**
- Serve `test-results/logs/` as a static directory from the backend
- Frontend fetches JSON directly
- Pros: simplest, zero code on server
- Cons: needs static middleware config

**Recommendation: Option A** — backend already has testRoutes.js with DEV_MODE gating. Adding 2 endpoints is minimal.

## Page Layout

### Header
- **Run selector**: dropdown of available test runs (by timestamp), most recent first
- **Summary bar**: total | passed (green) | failed (red) | skipped (grey) | duration

### Server Cards (4 cards: admin, doctor, clinic, web)
- Derived from suite names in the JSON (suites map to servers)
- Each card shows: pass/fail count, pass rate %, total duration
- Color-coded: green border if 100%, red if any failures
- Click to filter the table below

### Test Table
- Columns: Status icon | Suite | Test Name | Duration | Steps | Failure
- Sortable by duration (find slowest tests)
- Filterable by status (all/passed/failed)
- Failed rows highlighted in red, expandable

### Expanded Test View (click a row)
- Step-by-step timeline: each step as a bar (width proportional to duration)
- Failed step highlighted in red with error message
- Step timings shown (e.g., "Fill: doctor-username — 120ms", "Assert: visible — 15000ms FAILED")

### Historical Comparison (if multiple runs exist)
- Mini chart showing pass rate over last N runs
- Trend line: improving or regressing?

## Decisions Needed

1. **Data serving**: Backend API (Option A), Next.js API route (Option B), or static serving (Option C)?
2. **Scope**: Just the dashboard page, or also add a "run tests" button that triggers Playwright from the UI?
3. **Historical tracking**: Show last N runs comparison, or just the latest run?
4. **Screenshot integration**: Show failure screenshots inline (they exist at `test-results/*/test-failed-*.png`), or just text errors?
